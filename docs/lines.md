# 怎么加台词

台词不在代码里，也不用懂 JSON：每个角色一个文本文件，在 `fourwinds-benti/data/lines/` 下（`斐斐.txt`、`小九.txt`、`孔雀.txt`、`理理.txt`）。游戏启动时直接读。写错了会在主界面显示、`python3 tools/validate_data.py` 也会报，都带文件名和行号。

## 写法

```
# 来源：作者
## 付高额租金
- 这笔我记下了。
- （对孔雀）教授，你是认真的吗？ [生气]
- （斐斐在场时）哇，盖好了～斐斐你看！
- （只在上海）衡山路的梧桐，只有我配得上。
```

- `# 来源：xxx`：从这行起的句子都标这个来源。来源有 作者 / AI 写 / 占位（在 `events.json` 的 `sources` 里，可以关掉某个来源，或者调它出现的多少）。
- `## 事件名`：下面的句子都是这个事件的台词，事件名见下表。
- `- 句子`：一句台词，一句一行。新加一句 = 在对应事件下加一行。两头的 “” 可写可不写。
- 句首括号是条件，可以连写几个，要全满足才会用这句：
  - `（对孔雀）`：对象是孔雀（表里都算）；`（对孔雀表）` / `（对孔雀里）` 只算那个形态。
  - `（斐斐在场时）`：斐斐还没破产、在这局里。
  - `（只在上海）`：只在这张地图。写完整地图名或地图 id 都行；写 `上海` 会匹配所有叫“上海（……）”的地图。
- 句尾 `[表情]`：这句说的时候用的表情；不写就用事件默认表情。表情名在 `events.json` 的 `moods`：平常、开心、生气、得意、沮丧、惊讶、无奈。现在原版头像只有一种表情，所以画面上看不出区别，表情会写在日志里。
- `#` 开头的其他行是注释，空行忽略。
- 里形态的台词放 `昵称·里.txt`（现在没有）；里形态在自己的文件里找不到合条件的句子时，用表形态的。

## 怎么抽

一个人在一个事件下所有条件满足的句子放进同一个池子，作者 / AI 写 / 占位混在一起随机抽。条件越具体越常出现：带“对某某”的句子权重 ×4，“某某在场时” ×2，“只在某地图” ×3（几个条件相乘；倍数在 `events.json` 的 `settings`）。同一个人最近说过的 3 句先不抽。

不是每件事都开口：`events.json` 里每个事件有 `chance`（说话概率，百分数）和 `cooldown`（同一个人说过这个事件后隔几天才再说）。同一刻只让一个人说，撞上时按 `priority`（大的先）：破产 > 性格时刻 > 普通台词。例外：偷钱时小偷和被偷的人可以同时说；对手破产时接手家产的人在破产者之后回一句；游戏结束时赢的人和输的人各说各的。

## 事件表

“谁说 → 对谁”：对象就是“对某某”条件里的某某；没写对象的事件，“对某某”的句子用不上。

| 事件名 | 什么时候说 | 谁说 → 对象 |
|---|---|---|
| 付高额租金 | 付的租金超过他现金 + 存款的 20% | 付租的人 → 收租的人 |
| 付少量钱 | 租金低于他现金 + 存款的 10%（中间那段不说，原版规则） | 同上 |
| 交好运 | 挖到古董、抽到进账的机会卡 | 本人 |
| 倒霉 | 房子倒塌、抽到花钱的机会卡、钱不够买地 | 本人 |
| 进巡捕房 | 坐牢 | 本人 |
| 建成别墅 | 盖成别墅 | 本人 |
| 得到施舍 | 被信徒施舍 | 得到的人 → 施舍的人 |
| 被偷 / 偷到钱 | 小偷偷钱（两人可以同时说） | 被偷的人 ↔ 小偷 |
| 发起交易 | 提出交易 | 发起人 → 对方 |
| 接受交易 / 拒绝交易 / 还价 | 回答交易的人说（还价之后，发起人对还价的回应也是这两个） | 回答的人 → 另一方 |
| 被压价 | 对方开的条件比他交出去的东西少三成以上，他没答应（AI 记的“性格动作”） | 替换拒绝 / 还价 |
| 讨价还价 | 能答应也先还价 | 替换接受 / 还价 |
| 放水让价 | 看对方落后，让着他答应了 | 替换接受 |
| 领先时放宽 | 自己领先，按账不划算也答应了 | 替换接受 |
| 落后时损人不利己 | 自己落后，按账划算也拒绝（孔雀） | 替换拒绝 |
| 按错 | 随机答应了不划算的（小九“按错”） | 替换接受 |
| 被同一个人纠缠 | 同一个人 6 天内第 3 次向他提议，他拒绝或还价时 | 替换拒绝 / 还价 |
| 买到喜欢的街 | 买下 / 拍到自己喜欢的街（地图文件 `favorites`，现在只有孔雀）的地 | 本人 |
| 凑齐整条街 | 一条街的地全归他（买、交易、拍卖拿到最后一块） | 本人 |
| 拍卖买到 | 拍卖成交 | 买到的人 → 卖家 |
| 躲开大租 | 停下来的地方前后一两格有对手的高租地（租金够得上“大笔”）没踩到 | 本人 |
| 游览公园 | 进公园 | 本人 |
| 开局 | 第一个回合开始，随机一个人说 | 说话的人 → 随机一个对手 |
| 赢 / 输 | 游戏结束：赢家说赢，没破产的输家说输（现在游戏里没有“时间到”，所以输暂时不会触发） | 输家 → 赢家 |
| 自己破产 | 破产 | 破产的人 → 接手家产的人 |
| 对手破产 | 接手家产的人，在破产者之后回一句 | 接手的人 → 破产的人 |

性格时刻（被压价、讨价还价、放水让价、领先时放宽、落后时损人不利己、按错）发生在回答交易那一刻，会**替换**普通的接受 / 拒绝 / 还价；这个角色在这个事件下没有台词时，退回普通那句。

没做：收租（和交租同一刻，会抢话）、快破产（没有触发时机）、脱险（作者定不要）。

## 工具

```bash
python3 tools/lines_report.py
```

打印“角色 × 事件”的句数（括号里是 作者 / AI 写 / 占位 各几句），并列出哪些事件还没台词。

```bash
python3 tools/validate_data.py
```

检查台词文件格式（事件名、角色名、地图名、表情名、来源名有没有写错）。

## 写进 `.txt` 的几个约定

- 作者的草稿原话录在“来源：作者”下，一个字不改；`docs/lines_draft.md` 是作者给的原稿，留着对照。
- 作者草稿里的“拒绝（钓鱼）”“被气到”“勉强接受”“吐槽”这类是同一个回答事件下的不同说法，都录进了对应的 接受交易 / 拒绝交易 / 还价 里，用 `[表情]` 区分（被气到、吐槽 = `[生气]`，钓鱼、一起吐槽 = `[得意]`）。“心平气和”（小九回应理理）录在 接受交易 里。这几处是录入时的判断，不合适直接挪到别的事件下。
- “来源：占位”是旧 `speech.json` 里的 4 个角色的草稿，原来的“交易成功 / 交易被拒”录成了 接受交易 / 拒绝交易；“脱险”不要，没录。旧文件里原版 8 个角色的台词留在 `data/reference/original_speech.json`，只作参考，游戏不读。
