## 作者定下的做事方式（所有会话都照这个）

1. **界面和手感全部放到最后统一做**（原版 HUD、动画、立绘表演、提示位置、美术）。中间的步骤界面只求能用，不美化。不要要求作者列界面需求。
2. **结构已经拆好**（第 3.5 步）：地图层和界面层分开、等距换算只走 `iso.gd`、图片只走 `art.gd`。新界面（拍卖、交易、剧情对话、立绘）加在 `table.gd` 的 `_ui` 下面。
3. **作者测试时只报**：规则对不对、卡不卡、崩不崩、有没有想做却做不了的操作。样子的问题不用报。
4. **界面设计作者还没定。** 做界面时先按原版（`extracted/images/Screen/` 的原版界面图）搭一版，作者只回答“留 / 不要 / 换成这样”。提示框、信息框做成统一组件。
5. **菜单里不写规则说明**，只列能做的选项（作者在第 3.6 步说的）。
6. **作者提过、最后要做进界面的需求**：点击地块信息出现在地块上方；HUD 只显示当前玩家（立绘、现金、存款），对手信息另有入口（`Describe/` 全身立绘）；银行存取款现在是固定档位按钮，做界面时再定要不要加任意金额；台词改成立绘头上的气泡（事件 → 台词的对应在 `table.gd` 的 `_speak`）；回合开始镜头跳到当前角色（已做）；立绘出场、骰子、移动动画；原版底部工具栏（建造、拆除、抵押、赎回、拍卖、交易）。
7. 作者在 Windows 上测试和合并；说“合并”时开 PR。

## 规则现状

规则全部在 `scripts/core/game.gd`（用法在文件开头），按 `docs/original_rules.md` 实现。还没做：抵押 / 赎回 / 拍卖 / 交易（第 5 步；数据里已有 `mortgaged`）、特许建筑（市政厅只发特许证）、赛马小游戏。

**作者对规则的改动（和原版不同）**
- 停在银行上也能存取款，存取完这回合结束。
- 同一条街上并排的自己的平房（中间可夹自己的空地）可以合并成旅社 / 小洋楼 / 别墅，只付差价（`rules.json` 的 `houses.merge_flats`）。作者记得原版如此，未核对。
- 买下的空地上立一块主人颜色的地主牌（原版如此）。

**实现时自己定的细节（原版不明，可以改）**
- 纵火犯停在别人有房子的地上：烧掉整栋，这次不收租。升级不触发古董 / 倒塌。
- 第 7、14… 天开始时派息。状态天数在玩家回合开始时减 1。
- 路过银行、教堂只在“路过”时触发；一次移动里同一栋建筑的路过效果只触发一次。遇到别的玩家（小偷、信徒）连最后一步也算，坐牢 / 游览的人也会被遇到。
- 占 3 块以上地的房子，所占的地上不能有人站着。
- 原版地图的路改成了单向（工具自动定方向，保证全图走得通）。

**地图格式里原版地图特有的东西**（`board.gd` 开头有说明）：`lot` = 地 / 建筑所在的路边格；一块地 / 一栋建筑挨着几格路时，一格是正格，其余是带 `site` 的分身格，规则用 `Board.site()` 换算；旁边没东西的路是 `road` 类型。

## 第 4 步交接

**要做的**：用原版 12 个阈值参数（`data/ai/profiles.json`，4 个角色各一套，含义写在文件里，原文见 `docs/analysis.md` 6.8）替换临时 AI，在原版上海地图（`data/maps/shanghai.json`）上调。

**现有代码**
- 临时 AI `scripts/core/simple_ai.gd`：`SimpleAI.step(game)` 每次做一个决定，只调 `Game` 的公开方法。处理 `pre_roll`（建 / 升级 / 合并后掷骰）和 `pending` 的 `choose_direction`、`bank`、`buy_land` / `buy_company`、`bail`。新 AI 保持同样的接口，`table.gd` 和 `tests/ai_tests.gd` 就不用大改。
- 可用的查询：`game.build_options(pi[, merging])`、`why_cannot_upgrade`、`house_cost`、`rent_of`、`total_assets`、`land_price` / `property_price`；街道进度 `scripts/core/streets.gd` 的 `Streets.progress(game, pi)`（每条街自己有几块、连续几块）。
- 角色 → 参数：`characters.json` 的 `ai_profile`。

**原版 AI 在反汇编里的位置**（已查到，还没读）：用 `python3 tools/re/disasm_exe.py --out <文件>` 生成清单（要 `pip install capstone pefile`），带 `Brain.cpp` 断言字符串的函数在 `0x4073f0`–`0x40b7e0` 之间（共 23 个）。函数名（`getPriceIThink`、`bestSiteToBuild` 等）只在预编译头的标识符列表里（`extracted/devfiles/`），要靠读代码对上。抵押、交易、拍卖相关的（`tryToTrade` 等）留给第 5 步。

**第 3 步测试得到的结论**（已用对局验证）：临时 AI 一买到地就盖平房，地就凑不成大房子；改成“同街还能凑大房子时先不盖平房”后才出现旅馆。原版 AI 也要处理“留地凑大房子”。地图平衡等第 5 步交易做完再测。

**验收**：`tests/ai_tests.gd` 里 4 个 AI 在原版上海跑多局不卡、数据自洽；不同参数的角色行为有可测的差别（比如买地率、存款）。写进文档的结论注明是否用对局验证过。

## 模型分工（为了省用量）

原则：要查证、判断原因、搭框架的用强的模型；照现成模式、有写好验收测试的用便宜模型。交给便宜模型之前先把要照的模式和验收测试写清楚。拆得太碎也不省：新会话要重读上下文。

| 步骤 | 用哪个 | 理由 |
|---|---|---|
| 4 原版 AI | Opus；只有台词交给 Sonnet | 难在从反汇编读懂参数怎么用 |
| 5 交易、拍卖、抵押 | 一起用 Opus | 交易、拍卖里 AI 的出价和应对（`tryToTrade`）也要读反汇编 |
| 6 角色生动化 | Sonnet；性格化 AI 用 Opus | 台词和表情主要靠作者定人设 |
| 7 存档 / 读档 | Sonnet | 验收测试：在 `pending` 时存档，读回后用同样的随机数继续走，结果和不存档完全一样；浮点数要 `int()` |
| 8 个人主线 | Opus 搭关卡格式和胜负条件，Sonnet 填关卡 | 框架定了以后每关只是填数据 |
| 界面与手感 | Opus 搭统一的提示框 / HUD 框架，Sonnet 做重复的面板 | 先按原版截图搭一版 |
| 新规则、城市特殊规则 | Opus | 会改动 `game.gd`，不能破坏已有测试 |
| 5–6 张地图 | 转换 / 填数据交给 Sonnet；平衡测试用 Opus | 地图是数据，`validate_data.py` 兜底 |

## 省钱省时间的做法

1. 一个会话只做一步，开场说清“做第几步”。
2. `CLAUDE.md` 每次自动读取；这份计划只留后面步骤要用的内容，做完的步骤只留结论。
3. 规则用无头 Godot 在云端测（`tools/setup_godot.sh`）；作者只测画面和手感。
4. 数值都在 `data/*.json`，作者自己改。
5. 改动攒在一起，最后只跑一次检查（测试 + lint，截图最多一张）。
