# 复刻计划

目标：先用 Godot 复刻原版的基础玩法（自由模式 + 角色主线），只做 4 个角色（斐斐、小九、孔雀、理理），每个角色既是可选角色也是 AI 对手。规则先照原版，新规则（`docs/design.md` 的“核心规则”）以后再做。

## 已定的决定

| 问题 | 决定 |
|---|---|
| 棋盘形状 | 按“路网”存数据。第一张地图先做一圈；以后的地图可以有岔路、捷径。目标 5–6 张不同地图，每张一个 JSON 文件 |
| 角色 | 复刻阶段就用 4 个新角色，套原版规则；特殊能力先不启用，只做性格、AI 和台词 |
| 地图数据 | 先借原版上海的街道名和价格作占位 |
| 赛马小游戏 | 跳过；赛马场先做成简单的随机名次得奖金格子 |
| 建房时机 | 照原版：掷骰前可以在自己任意符合条件的地上建房，不需要站在那块地上。`design.md`“原版的问题”第 4 条是作者记错了，不用解决 |
| 房子占地 | 照原版：平房 1 块、旅社/旅馆 2 块、小洋楼/花园洋房 3 块、别墅 4 块；占的地要是同一条街上沿路连续的、都是自己的空地。以后每张地图都要有足够长的街（≥ 4 块连续的地），`tools/validate_data.py` 会检查。`shanghai_loop` 只是占位，已把北京路、南京路各加长到 4 块（现在 40 格） |
| 十字路口 | 分两种，在地图的路口格上用 `crossroad` 字段指定：`choice` 自己选方向（默认）、`random` 随机走一边。不照搬原版的箭头规则。作为策略点：以后某些角色的特性可以让他们在随机路口也能选（预留了 `game.gd` 的 `_may_choose_direction`） |

## 原版规则

已经反汇编查清，见 `docs/original_rules.md`，数值写进了 `data/rules.json` 和 `data/cards/chance.json`。
第 2 步按这套规则实现了，代码在 `scripts/core/game.gd`（用法写在文件开头的注释里），测试在 `tests/game_tests.gd`。

### 第 2 步做了什么

- 回合流程：掷骰前 → 掷两颗骰子 → 一步一步走（路过银行、教堂、遇到别的玩家）→ 停下的效果 → 下一个人。所有人走完一轮 = 一天，每 7 天派息。
- 需要玩家（或 AI）选择的地方，游戏停在 `phase == "pending"`，由画面 / AI 来回答：十字路口选方向（仅 `choice` 路口；`random` 路口自动随机，记 `random_direction` 事件）、路过银行存取款、买地 / 买企业、巡捕房交不交保释金。
- 买地、收租（含企业同行业翻倍、抵押 / 坐牢 / 游览 / 慈善不收租、免费 / 加倍 / 半价状态）、建房 / 升级 / 拆房（含古董和倒塌事件）、税务局、巡捕房、教堂、公园、市政厅（只发特许证）、赛马场（随机名次）、30 张机会卡、状态（小偷、纵火犯、抢劫犯、信徒等）、破产和胜负。
- 发生的事记在 `game.events` 里，第 3 步的画面和台词靠它。
- 随机对局测试：40 局随机玩，每一步检查数据自洽。

### 第 2 步没做（留给后面）

- 抵押、赎回、拍卖、交易：第 5 步。数据结构里已经有 `mortgaged`，抵押中的地不收租、不能建房、总资产按一半算，机会卡 17 也会收走抵押物；但还没有“抵押”这个操作。
- 特许建筑（黑帮、算命铺、当铺）：市政厅现在只发特许证（`player.permit`），还不能建。
- 赛马场：没做小游戏，也没做破纪录奖金。

### 实现时自己定的细节（原版不明或文档没写，可以改）

- 纵火犯停在别人有房子的地上：烧掉整栋房子，这次不收租。
- 升级不触发古董 / 倒塌事件，只有新建房子才触发。
- 日期从第 1 天开始，第 7、14… 天开始时派息（原版是星期六，星期几是假设的）。
- 路过银行（存取款）和路过教堂（捐款）只在“路过”（不是最后一步）时触发；停在银行上原版没有效果，**作者决定改成：停下也能存取款**（存取完这回合结束）。遇到别的玩家（小偷、信徒）连最后一步也算。
- 占 3 块以上地的房子，所占的地上不能有人站着（原版是“门前道路上没有人”，我们的地就在路上）。
- 状态天数在这个玩家每个回合开始时减 1；坐牢 / 游览期间一直算“不收租”，直到下回合开始状态被清掉。
- 坐牢、游览的玩家，路过的人仍然会“遇到”他（小偷、信徒会触发）。
- 机会卡里 5 张带 1940 年代中国背景、“哪个角色能抽到哪张卡”仍然是借用原版角色，见下面“等作者决定的内容”。

### 第 3 步做了什么

- 主界面（`scripts/ui/main.gd`）：4 个位置，每个选人类 / AI / 空，再选角色（同一角色不能坐两个位置，至少 2 人），点“开始游戏”。
- 棋盘画面（`scripts/ui/table.gd`，场景 `scenes/table.tscn`）：画格子、街道色条、地主边框、房子条、棋子、骰子；左边是玩家卡片（现金、存款、总资产、状态、最近一句台词），右边是操作区和日志。点棋盘上的格子看价格、租金、主人。
- 人类操作：掷骰、十字路口选方向、路过银行存取款、买地 / 买企业、交保释金、掷骰前的“房产”对话框（建房 / 升级 / 拆房，鼠标移到按钮上会高亮要占的地）。
- 事件播放：规则每做完一步，画面把 `game.events` 按顺序播放（棋子一步步走、写日志、按 `speech.json` 冒台词）；右上角“快速”可以加快。
- AI：`scripts/core/simple_ai.gd` 是临时的简单 AI（有钱就买、建最贵的买得起的房子、多余现金存银行），第 4 步换成原版的 12 个阈值参数。
- 游戏结束弹出结算，可回主菜单。
- 云端检查：`tools/ui_check.gd` 自动玩一阵并截图（用法写在文件开头）。

### 第 3 步没做

- 抵押、拍卖、交易（第 5 步）；特许建筑；赛马小游戏。
- 骰子没有滚动动画，棋子没有平滑移动（一格一格跳）。美术最后做。
- 台词只用了 `speech.json` 里已有的 12 种事件里能对上规则事件的几种。

## 作者定下的做事方式（所有会话都照这个）

1. **界面和手感全部放到最后统一做**（等距、原版 HUD、动画、立绘表演、提示位置、美术）。中间的步骤（第 4、5、7、8 步）界面只求能用，不美化。作者现在也想不全最后的界面，不要要求作者列需求。
2. **唯一不往后放的是第 3.5 步的“拆结构”**：地图层和界面层分开。这是技术决定，不用问作者；以后新界面（拍卖、交易、剧情对话、立绘）都建在这个结构上，避免最后重写。
3. **作者测试时只报**：规则对不对、卡不卡、崩不崩、有没有想做却做不了的操作。样子的问题不用报。
4. **界面设计作者还没定。** 做界面时不要让作者凭空描述：先按原版（作者给的截图、`extracted/images/Screen/` 里的原版界面图）搭一版，作者只回答“留 / 不要 / 换成这样”。提示框、信息框做成统一组件，以后改位置只改一处。
5. **作者提过、最后要做进界面的需求**：
   - 点击地块，信息直接出现在地块上方（作者记得原版是这样，未核对；需要时可查原版界面图和 exe 字符串）。
   - HUD 只显示当前轮到的玩家：立绘、现金、存款（原版如此）；其他玩家不常驻列出，要看对手信息另有入口（`Describe/` 的全身立绘是“查看对手信息用”，入口和内容做界面时查原版）。第 3 步现在把 4 人都列在左边，只是测试用的临时做法。
   - 银行存取款：原版可以自己输入任意金额；第 3 步现在是固定档位按钮（存 / 取 100、500、全部），作者觉得这样也直观，**不一定要改**，做界面时再决定保留哪种或两种都留。
   - 台词显示：原版每个角色的回合里，不管结果是付钱还是运气好，都在他的立绘头上冒气泡显示台词，很直观。第 3 步现在是把台词写在左边卡片和日志里，是临时做法；做界面时改成立绘头上的气泡（事件到台词的对应已经有了，在 `table.gd` 的 `_speak`）。
   - 回合开始镜头自动跳到当前角色，玩家也能拖动视角（原版地图 54×54，一屏放不下）。
   - 角色立绘出场表演、骰子动画、移动动画。
   - 复刻原版底部工具栏：建造、拆除、抵押、赎回、拍卖、交易。
6. 作者在 Windows 上测试和合并；说“合并”时我开 PR。

## 省钱省时间的做法

1. 一个会话只做一步，开场说清“做第几步”。
2. `CLAUDE.md` 会被每次会话自动读取，不用重复上传设计文档。
3. 规则逻辑在云端用无头 Godot 测（`tools/setup_godot.sh`）；作者只测画面和手感。
4. 数值都在 `data/*.json`，作者自己改，改完按 F5 看效果。
5. 美术最后做。
6. 照现成模式写的活用便宜一些的模型；架构、反汇编、难查的 bug 用强的模型。
